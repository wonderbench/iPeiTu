# iPeiTu v0.1 开发与验收

目标：用户导入已经准备好的本地图片，在插件中按文件名查找并预览，点击后将图片嵌入 Windows WPS 文字当前光标位置。

## 已确认的环境与范围

- 仓库：https://github.com/wonderbench/iPeiTu，默认分支 main；启动时仅有 README。
- 本地已有 119 张 PNG / JPEG 素材，不上传到公共仓库。
- 已安装 Windows WPS 文字 12.1.0.29161。加载项功能须在该宿主中验证。
- 技术方向：Node.js 本机服务管理图片与持久化索引；HTML/CSS/JavaScript 任务窗格；独立 WPS 桥接模块。服务只监听回环地址，不依赖云服务。
- 素材导入后保存在本机管理目录，重复内容去重；索引保存图片名称、尺寸、格式、文件大小及生成缩略图信息。
- 搜索按名称处理中文、大小写及空白；用户明确选择图片后才操作文档。

## 已验证的阶段结果

- 步骤 2：真实 119 个素材文件导入得到 117 张独立图片、2 次内容重复、0 失败。重启服务后读取同一持久化图库。
- 后端审查修复了空文件名、EXIF 旋转、Windows 大小写/目录别名自导入、透明 PNG 缩略图黑底等实际问题，并保留回归测试。
- 接口、文件来源和边界、持久化、损坏文件与重复导入的 16 项专项测试通过。CI 在 Windows 与 Ubuntu 上执行。
- 界面随步骤 3 合并，以保证 WPS 接入后即可使用；步骤 4 专注整体验收与交付，不交付空任务窗格。
- 步骤 3：WPS 12.1.0.29161 实机已显示功能区、117 张本地素材及成功插图反馈；用户亦明确反馈“我测试过了，可以插入”。其余实机项目逐项记录，不由这条反馈推断。

## 设计方向

1. 产品：为编制标书的人员提供可快速检索和插入的本地配图库。
2. 性格：沉稳、准确、直接。
3. 场景：工程资料目录与纸面标书，灰白背景，深青强调色。
4. 视觉重点：真实工程配图缩略图与当前选择的大图预览；界面控件保持安静。
5. 识别细节：底部固定的图片名与“插入光标处”操作区，让选图和落图始终对应。

当前没有既有 UI 可审计。按 unslop 的间距、颜色、图标、文案、字体、布局、细节、视觉、动效顺序实施；任务窗格按窄屏布局，不套用营销页面。

## 合并与发布标准

- PR 必须说明本步实际行为和运行过的验证；审查以最新提交为准。
- 自动检查失败或有未解决的高优先级缺陷时，先修复再合并。
- 同账号无法为自己的 PR 提交 GitHub Approve 时，以审查评论记录验收结果，再执行已授权的合并，不伪称独立账户批准。
- WPS 模拟测试通过仅证明桥接调用契约；最终版本的实机操作、保存重开需另有证据。若环境阻碍实机测试，明确标记未验收项目。
- 用户已授权各步 PR 经审核后自动合并；不绕过仓库分支保护规则。
