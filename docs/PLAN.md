## 设计方向

1. 产品：为编制标书的人员提供可快速检索和插入的本地配图库。
2. 性格：沉稳、准确、直接。
3. 场景：工程资料目录与纸面标书，灰白背景，深青强调色。
4. 视觉重点：真实工程配图缩略图与当前选择的大图预览；界面控件保持安静。
5. 识别细节：底部固定的图片名与“插入光标处”操作区，让选图和落图始终对应。

当前没有既有 UI 可审计。按 unslop 的间距、颜色、图标、文案、字体、布局、细节、视觉、动效顺序实施；任务窗格按窄屏布局，不套用营销页面。

## 合并与发布标准

- PR 必须说明本步实际行为和运行过的验证；审查以最新提交为准。
- 自动检查失败或有未解决的高优先级缺陷时，先修复再合并。
- 同账号无法为自己的 PR 提交 GitHub Approve 时，以审查评论记录验收结果，再执行已授权的合并，不伪称独立账户批准。
- WPS 模拟测试通过仅证明桥接调用契约；最终版本的实机操作、保存重开需另有证据。若环境阻碍实机测试，明确标记未验收项目。
- 用户已授权各步 PR 经审核后自动合并；不绕过仓库分支保护规则。

## 前端重新设计（2026-11-05）

[PR #12](https://github.com/wonderbench/iPeiTu/pull/12)。用户要求按 unslop 重新设计前端，不做本地端到端测试，提交 PR 后审核自动合并。功能、接口与元素 ID 不变，改动集中在 `public/taskpane.html`、`public/styles.css` 与 `public/app.js` 的展示部分。

1. 产品：帮标书编制人员在 WPS 文字里查找工程配图并插入光标处。
2. 性格：沉稳、准确、直接。
3. 场景：工程图纸与纸面标书，灰白中性色，深青强调色。
4. 视觉重点：真实素材缩略图与当前所选图的大图。
5. 识别细节：图纸图签。所选图下方用发丝线分隔规格与操作入口，数字用等宽字体。

审计结论与处理：

- 320×800 窗格中素材只有约 260px 可见。收紧顶栏、检索与视图，滚动时固定在图库上方后，素材区约 560px，其中可见图片约 470px。
- 常驻的“全部分类 · 不限工序”只在有筛选时显示；对话框说明压缩到防误操作所需，放不下的细节留在 README。
- “点击左图预览”依赖布局方位，改为图上的放大标记。
- 800px 以上由底部栏改为右侧图纸栏，直接显示分类与工序。
- 修复既有缺陷：竖版缩略图被裁切，工程配图现在完整显示。

验证边界：Playwright 流程只在 CI 运行，本机未运行；设计用假数据在浏览器做过 320 与 1080 宽度的视觉检查；未在真实 WPS 中查看新界面，需要实机确认任务窗格渲染。
