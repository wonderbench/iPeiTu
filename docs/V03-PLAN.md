# v0.3 路线：占位框、填充与标书格式

2026-11-07 用户确认。产品核心调整为三件事：便捷管理素材、在合适的文本位置插入图片占位框、便捷填充并适配框的尺寸；同时开始标书格式管理。本文取代 [V02-PLAN.md](V02-PLAN.md) 中尚未开发的步骤 7—9 的顺序，已完成步骤的记录仍以原文档为准。

## 用户决定

1. **实机验收不在当前工作机进行。** 当前工作机没有 WPS 和 Node，这里只做模拟测试，检查在 CI 上运行。
2. **标书格式先做基础管理。** 先把插件内的独立页面做好，暂不深化。
3. **裁切和拉伸都要可选。** 填充时由用户选择适配方式。
4. **添加入口改到图片卡片。** 取消“先选图、再点按钮”，改为点击卡片上的“+”直接添加。
5. **标书格式以排版工具实现。** 用户提供排版功能清单，一键排版优先，见“步骤 7—11”。

## 步骤 1：卡片“+”号添加

- 每张卡片常驻一个“+”按钮，点击后按当前排版设置插入当前光标处，不需要先选图。移除底部的“插入光标处”按钮。
- 点击卡片其他区域仍只选图，用于预览、收藏和编辑素材信息。点击“+”同时选中这张图，图题按这张图取名。
- 卡片现在是 `<button>`，不能再嵌套按钮，需改为容器内并列“选择”和“添加”两个按钮。
- 保留“键盘不能意外写入文档”：卡片上按 Enter 或空格仍只选图，“+”是单独的焦点目标。只有当前卡片的“+”进入 Tab 顺序，保持图库只有一个 Tab 入口。
- 每次点击都重新读取文档和光标；等待期间文档或光标变化则中止，沿用现有校验。
- 插入进行中忽略其他“+”，防止连击重复插入。成功时卡片短暂显示对勾，并在状态栏提示。
- 浏览器模式、无文档、只读或受保护时，“+”禁用并说明原因；回收站视图不显示“+”。
- 底部栏保留预览、排版设置和素材信息。“替换选中图”只在文档中选中图片时显示；替换普通图片仍需明确操作。
- 需同步修改 `scripts/verify-ui.mjs`、`scripts/verify-import-ui.mjs` 中依赖 `insertButton` 的流程，以及 README 使用说明。

## 步骤 2：占位框

框采用一张内嵌占位图，标记写入图片的 `AlternativeText`。

- 框有真实宽高，用户可直接拖动控点调整。框的尺寸始终以文档中图片的当前宽高为准。
- 可遍历 `InlineShapes` 扫描，填入时复用替换流程。
- 占位图由本机服务生成，显示框名和尺寸，校验尺寸上限，缓存放在图库目录内。
- 正文中的框默认独立成段并使用单倍行距，避免固定行距裁图；单元格内的框默认取单元格内部尺寸。
- 提供常用尺寸预设，也可输入宽高（厘米）。

未采用的形式：文字标记没有尺寸，只作为步骤 4 的批量输入；单格表格会改变文档的表格结构；图片内容控件的类型支持未能从文档确认。

## 步骤 3：填入与适配方式

步骤 2 已完成的部分：标记格式为 `iPeiTu-box:1:` 加 JSON（目前只有 `name`），框所在段落独立、居中、单倍行距、段前段后为 0，空段落和空单元格不拆段。步骤 3 在 JSON 中增加已填信息，并在选中占位框时让“替换选中图”改为填入，避免现在替换会丢失标记。

步骤 3 实际交付：已填标记为 `{name, asset, fit}`；适配图分辨率按质量档取 300/220/150 dpi，且不超过原图；“按框名检索”为显式按钮，不在选中框时自动改动检索框。“比例接近的图片排在前面”移到步骤 4：窗格状态在鼠标移入时刷新，此时重排图库会让卡片跳动，需要与连续配图一起设计。

光标或选区在框上时，窗格显示目标框和尺寸，“+”变为填入此框。适配方式可选，并记住上次选择。

| 方式 | 结果 | 比例 |
| --- | --- | --- |
| 裁切填满（默认） | 铺满框，超出部分居中裁掉 | 不变形 |
| 拉伸填满 | 铺满框，内容完整 | 可能变形 |
| 完整显示 | 内容完整，空白处补白 | 不变形 |

- 三种方式都由本机服务用 `sharp` 生成图片，插入时按框的宽高设定图片尺寸。
- 输出像素按框的尺寸计算，不超过原图分辨率，并沿用质量档与元数据清除规则。缓存键需包含适配方式和目标尺寸。
- 不依赖 WPS 的 `PictureFormat.CropLeft` 等裁切属性。代价是裁切后不能在 WPS 中调整，需重新填入。
- 写入后回读宽高，接受 WPS 产生的不足 1 磅的尺寸偏差。核对失败时移除新图并保留原框，一次撤销可恢复。
- 填入后保留标记，可再次换图；窗格按框名预填检索，比例接近的图片排在前面。

## 步骤 4：连续配图

- 填入后自动定位下一个空框。
- 把文字标记（如 `【图：脚手架搭设】`）批量转换为占位框，先列出再确认，原有其他文字不变。
- 生成“两列图片加图题”的照片表。
- 列出未填的框，点击定位。
- 交付前可一键清除文档中的 iPeiTu 标记，只删标记，不动图片。

自动按名称批量配图不在本轮范围。

**步骤 4a 实际交付：**

- 填入成功后扫描文档，选中当前框之后的第一个空框；后面没有时回到文档开头；全部填完提示。定位失败不影响已完成的填入，并在状态栏说明。
- 文字标记格式为 `【图：名称】`，冒号全角或半角，名称 1—100 个字符。先整体读一次正文判断有无标记，有时再逐段查找；段落文字与位置不能一一对应时跳过并计数（单元格末段的结束标记已兼容）。
- 转换沿用占位框表单当前的尺寸选择，按每个标记所在位置计算框大小；任一标记无法放置时整体拒绝。写入前逐个核对标记原文，文档有变化就整体中止。从后往前处理，先删标记文字再放框：独占一段的标记直接成为框所在段落，段中的标记拆成独立段落。中途失败时移除未写入标记的占位图，报告已转换数量，一次撤销可恢复。
- 清除标记只清除已填框（`AlternativeText` 置空），图片保留；未填框保留并提示数量，避免留下无法识别的灰色占位图。清除前弹出确认。
- “比例接近优先”为手动开关，只在选中占位框时生效，按图片与框宽高比的对数差排序，比例相同时保持图库原顺序；只在开关或目标框比例变化时重排。
- 照片表拆为步骤 4b，等用户确认图片表格的做法。

## 步骤 6：一键安装与启动

- 项目根目录的“安装.cmd”“启动.cmd”“停止.cmd”“卸载.cmd”分别调用 `scripts/setup.ps1`、`scripts/service.ps1 -Action start|stop`、`scripts/remove.ps1`；脚本为带 BOM 的 UTF-8，输出中文。
- 安装先在状态目录的 `runtime` 和系统 PATH 中查找可用的 Node.js 24+ 和 npm，缺少时才从 `https://nodejs.org/dist/` 下载固定版本的 Windows 便携包（x64、ARM64），校验固定的 SHA-256 后才解压，通过后一次移入状态目录下的 `runtime`。首次安装需要联网。卸载不删除 `runtime`，不再需要时可手动删除状态目录中的该文件夹。升级脚本中固定的 Node 版本后，旧版本的 `runtime\node-v…` 目录不会自动清理，可手动删除。运行依赖缺失或无法加载时运行 `npm ci --omit=dev`。登录后自动启动写入当前用户注册表的 Run 项 `iPeiTu`，可用 `-NoAutoStart` 跳过。
- 服务新增 `/api/health`（服务名、版本、进程号、程序目录）。`server/index.js` 遇到端口占用时：已是 iPeiTu 则提示已在运行并以 0 退出，否则说明被其他程序占用并以 2 退出。
- 停止和卸载只结束命令行包含本目录 `server\index.js` 的进程，只删除命令指向本目录脚本的自动启动项。
- Windows 自动化测试使用临时目录、临时端口和临时注册表键，覆盖安装、启动、占用检测和卸载。便携版 Node 的测试不访问网络：状态目录里有完整的便携版时直接采用，缺少 `node.exe` 或 npm 的目录不被采用，过期的下载残留被清理，并检查下载地址固定为 `https://nodejs.org/dist/`、SHA-256 校验在解压之前。真实的下载与校验失败路径需要联网，没有自动化测试。
- 第一版用 `Start-Process` 启动服务，CI 中安装测试文件 415 秒未结束（其余 172 项通过），本机未能复现。改为经 WMI 创建服务进程，端口、图库目录与日志改由命令行参数传入、服务自行写日志；测试只等脚本进程退出并记录每次调用耗时；CI 的 test 作业加 15 分钟上限。

## 步骤 7—11：排版工具

2026-11-07 用户提供排版功能清单，取代原步骤 7、8 的“格式方案管理与样式应用”。排版工具是插件内独立的任务窗格页面（功能区“标书排版 › 排版工具”）。用户选择一键排版优先。

**功能清单（用户原文归纳）：**

- 首页 3 组入口：表格操作、表格工具（8 项点击即执行）、格式与样式（颜色替换、背景切换）。
- 模块一 表格操作：1—4 列快速插入、带色行、插上行/下行、删除整行、自动序号；合并单元格、拆为 2/3/4 列、按符号拆分、全部表格批量拆分；白色底纹表格与 2/3/4/6 列图片表格；4 种线型 × 6 种粗细的边框，作用于当前或全部表格；文本转表格（可设分隔符）、表格转文本、标题转大纲。
- 模块二 一键排版：清除格式、首行缩进、居中对齐、删除空行、表格满页、边距清零、清除空格、去除底纹、去除表格线、一键去色。
- 模块三 表格宽度标准化：一栏页面目标宽度（默认 15 厘米）、多栏页面目标宽度（默认 7 厘米）、读取光标所在表格宽度、全文表格左/中/右对齐、一键按一栏或多栏调整。
- 模块五 背景切换：单选或批量选择背景图并预览、应用或清除页面背景；A3 横、A4 竖、A3 竖、A4 横四种页面尺寸一键切换。

**步骤 7 已采用的规则（作用范围为默认方案，待用户确认）：**

- 有选区时只作用于所选内容，没有选区时作用于全文；窗格顶部显示当前作用范围。没有选区时，作用于全文的批量操作（删除空行、表格满页、边距清零、清除空格、去除底纹、去除表格线、一键去色、表格宽度、表格对齐）执行前先确认；确认期间选区变化则放弃执行。
- 清除格式、首行缩进、居中对齐只作用于所选段落；未选中时首行缩进与居中对齐只改光标所在段落，清除格式必须先选中内容。
- 每项操作一次撤销记录，执行后报告处理数量；中途出错时如实说明，并提示可撤销一次恢复。只读、受保护、页眉页脚中不执行。
- 清除格式：段落样式恢复为正文，并重置段落格式和字符格式（WPS 的 Range 没有 `ClearFormatting`）。
- 首行缩进：`CharacterUnitFirstLineIndent = 2`。居中对齐：段落水平居中。
- 删除空行：删除只含空格或制表符的段落；跳过表格内的段落、含分节符或分页符的段落、文档最后一段，以及两个表格之间的空行（删除后表格会合并，计数报告）。两侧是否为表格按文档位置判断，选区只含该空行时也能识别。段落范围的 `ShapeRange` 不为空或读不出时保留该空行并单独计数，避免连带删除浮动对象。
- 表格满页：首选宽度设为页面宽度的 100%。
- 边距清零：表格与每个单元格的上下左右边距归零；“锁定”理解为关闭自动调整、固定列宽。
- 清除空格：按连续的一段空格（半角、全角、不换行空格）处理。这段含半角空格，且两侧字符一个是英文字母或数字、另一个是英文字母、数字或汉字时，保留一个半角空格；其余整段删除，包括汉字与汉字之间、任一侧是标点符号或段落标记、单元格首尾，以及只有全角空格的一段。文字与位置不能一一对应（含域或隐藏文字）的单元格跳过并计数。2026-11-22 用户确认保留中文与数字之间的半角空格；汉字与英文之间同样保留、符号两侧仍删除是据此推定的，待用户过目。
- 去除底纹：表格与单元格底纹改为无。去除表格线：关闭表格与单元格边框。
- 一键去色：内嵌与浮动图片改为灰度，图形的填充和线条改为对应灰色；浮动图形只在未选中内容时处理，组合图形跳过并计数。

**步骤 8 已采用的规则：**

- 一栏或多栏按表格所在节的 `PageSetup.TextColumns.Count` 判断，大于 1 即多栏。目标宽度默认 15 与 7 厘米，范围 1—60 厘米，保存在本机。
- 以各行中最大的单元格宽度总和估算当前表宽，用目标宽度除以当前表宽得到统一的缩放比例。按该比例调整本表单元格，并将首选宽度设为目标值。跨行单元格只参与一次调整，`NestingLevel` 不同的嵌套表格单元格不动。
- 每一行已在目标宽度 0.5 磅以内的表格视为已符合，不改动；任一单元格宽度不确定（如返回 9999999）的表格跳过并计数。
- 读取当前表格：取光标所在表格最宽一行，按栏数填入一栏或多栏输入框；只读文档也可读取。
- 表格左对齐、居中、右对齐通过 `Rows.Alignment` 整体设置，左对齐时 `Rows.LeftIndent` 归零；作用范围与其他排版操作相同。

## 步骤 14：局域网图库

2026-11-08 用户提出：部署服务要兼容局域网内的本地服务器。

**用户决定：**

- 本机服务转发：一台电脑作服务器；每台客户端照常安装，在设置里填写服务器地址，由本机服务转发、下载缓存和插图，图片仍嵌入文档。
- 共享访问密钥：服务器生成随机密钥，客户端填写后才能访问，不分角色。账号与角色仍属于步骤 12。
- 图片（含分类和回收站）与知识库共享；收藏和最近使用按每台电脑分别记录。
- 本机图库与局域网图库二选一，可以切换，数据不合并。

浏览和插图都需要服务器在线；本地缓存只省去重复下载，不支持断网浏览。

**实际交付：**

- 服务器：
  - `局域网服务器.cmd` 调用 `setup.ps1 -Lan`，用系统随机数生成 32 字节密钥（base64url，43 位），保存在 `%LOCALAPPDATA%\iPeiTu\lan-access-key.txt`。已有密钥时沿用。密钥文件被删除后再次运行时，先停止运行中的服务再生成新密钥，停止失败则不生成。
  - `service.ps1` 在密钥文件存在时以 `--host 0.0.0.0 --access-key-file` 启动；运行中的模式与设置不同时先停止再启动。`setup.ps1 -LocalOnly` 和卸载都会删除密钥。脚本不改防火墙，只打印放行命令（限专用网络）。
  - 连接来自回环地址且 Host 为本机时，沿用原有检查。其余请求只在局域网模式下接受，需要 `Authorization: Bearer` 密钥（比较 SHA-256 摘要，常数时间）和客户端标识 `X-IPeiTu-Client`；带 `Origin`、`Sec-Fetch-Site` 或 `Referer` 的浏览器请求一律拒绝。
  - 远程只开放图库、素材、上传、知识库和健康检查接口，在 `server/http.js` 的 `remoteRoutes` 中按“方法 + 完整路径”逐项登记，未登记的一律返回 403；新增接口默认不对远程开放。静态页面、按路径的目录导入、占位图和连接设置只供本机。远程健康检查不返回进程号和安装路径。
  - 永久删除素材、永久删除知识库片段和清空回收站只能在服务器那台电脑上操作：局域网客户端的这些请求返回 403，需要到服务器上执行；这些路由不在 `remoteRoutes` 中。素材信息与知识库片段的编辑锁，以及批量移入回收站，对局域网客户端开放。
  - 密钥错误的警告日志按来源地址限频：同一地址 60 秒内最多一行，记录的地址最多 256 个。
  - 远程的插图与适配图信息不含服务器路径，改附 `sha256` 和 `/insertion/file`、`/fit/file` 下载地址。
  - 远程客户端的收藏与最近记录保存在 `clients/<客户端标识>.json`，最多 1000 个，损坏时只影响该客户端。
  - 作为服务器运行时，本机不能再连接其他服务器。
- 客户端（`server/lan-client.js`）：
  - 连接设置 `GET`、`PUT`、`DELETE /api/connection`，只供本机。地址只接受 http(s) 的主机和端口，未写端口时使用 39831，拒绝本机地址。保存前先用该地址和密钥做健康检查，失败不保存；读取状态时不返回密钥。导入进行中不能切换。
  - 配置保存在本机图库目录的 `connection.json`。文件损坏时明确报错，不悄悄改用本机图库。
  - 图库、素材、上传和知识库请求原样转发。服务器连不上或密钥失效时返回 502，并给出明确提示。
  - 插图和适配图下载后核对字节数与 SHA-256，存入本机 `lan-cache`，再以本机路径交给 WPS。缓存按哈希命名，可以复用。
  - 目录导入沿用本机的目录扫描和来源校验，改为逐张上传；连接或密钥出错时整批停止。占位图始终在本机生成。
- 界面：素材库顶栏的“本机 / 局域网”按钮打开“图库来源”对话框；导入面板说明随来源改变；知识库窗格在局域网模式下显示“局域网”标记。在一个窗格切换来源后，回到另一个窗格时会重新读取。

**局域网接口版本与版本号（合并 PR #40 的审查）：** 合入步骤 15 后，窗格在编辑素材信息前申请编辑锁（`POST /api/assets/<id>/edit-lock`），并使用批量移入回收站。只升级客户端、服务器仍是旧版本时，这些请求会被旧服务器以 403 拒绝，而连接检查只比较 `api` 版本，连接时不会提示不兼容。因此 `server/lan-client.js` 的 `API_VERSION` 由 1 改为 2，连接时得到“请两边更新到同一版本”的提示；`test/lan.test.js` 新增用例，服务器 `api` 为 1 或 3 时拒绝连接且不保存。版本号因合入步骤 15 等功能由 0.3.0（#32 所设）改为 0.4.0。

`#31`、`#33`（表格宽度与空行判断）、`#35` 和 `#32`（换密钥）移植自 `origin/Jzc` 分支的对应改动，该分支记录了这些问题在 WPS `12.1.0.29690` 上的读数。`Jzc` 随后在同一天整体合入，见步骤 15。

**`#37` 采用的规则：**

- 图库目录下 `fitted`、`insertion-quality`、`placeholders`、`lan-cache` 四个缓存各设 512 MB 上限。超出时按修改时间从旧到新删除，最近 10 分钟内修改的不删。缓存命中时刷新修改时间，所以淘汰顺序是按最近使用。服务开始监听后清理一次，之后每 6 小时一次。上限、保护期和间隔是固定默认值，没有配置入口。
- 只删除两类文件：四个缓存目录中文件名符合程序生成格式的缓存；图库目录本身、`images`、`thumbnails`、`insertion`、`clients` 和四个缓存目录中，命名为 `<目标文件名>.<uuid>.tmp` 或 `index-<uuid>.tmp` 且超过 1 小时的临时文件。不跟随符号链接，只有 `insertion-quality` 向下进入一层版本子目录，删除前再次核对路径与文件身份。
- 重复导入：内容相同、`normalized` 已记录、原图、缩略图和（需要时的）插入副本都是非空文件且原图逐字节相符时，只合并别名与分类或从回收站恢复，不解码也不写文件。缩略图或插入副本损坏但非空时，重新导入不再能修复它。
- 后台日志超过 5 MB 时改名为 `<名称>.1`，只保留一份；轮转失败后 60 秒内不再重试。
- 已知的小窗口：清理刚核对完一个旧文件、缓存命中恰好此时刷新时间、随后删除生效。适配图会自动重新生成一次；占位图、压缩档和局域网缓存返回的路径可能已不存在，那次插图失败，重试即可。

**审查中提出、这次没有处理的：**

- 批量导入时每张图重写一次 `index.json`；素材列表一次返回全部并重建全部卡片，没有分页或虚拟滚动。需要先定方案。
- 查找文字标记、删除空行和扫描占位框逐个访问 WPS 对象，长文档上的耗时需要实机测量后再决定是否改写。

- 导入时使用 `failOn: 'warning'`，轻微损坏但能显示的照片会被拒绝；“原图”档插入时保留图片的全部元数据。两项都是取舍，待用户决定。
- 局域网访问密钥经明文 HTTP 传输、不分角色，属于步骤 12 的范围。

## 2026-11-22 界面配色调整

状态：已合并，实机待验（只做了代码阅读；界面回归在 CI 运行，没有在真实 WPS 任务窗格中查看）。

2026-11-22 用户提供了一份面向桌面管理后台的设计规范，希望把其中一部分规则用到任务窗格上，并确认配色改用蓝色。协调者按规范画了静态样机 [design/mockup-2026-11-22.html](design/mockup-2026-11-22.html)，用户看过后要求按它实施。样机画于合并 `Jzc` 之前，按的是旧界面的结构，与现在的画廊式素材库、自绘下拉菜单等结构不同。实施时只采用样机的规则，结构以实际界面为准。功能、接口、元素 ID 和验收脚本都没有改动。

**采用的规则：**

- 配色：单一蓝色强调色。文字、图标和实底按钮用加深的蓝 `#0B6FCC`，悬停 `#095BA8`。规范原色 `#0094FF`、`#409EFF` 在白底小字上对比度不够，只用于顶栏渐变。主按钮与写入文档的动作（卡片“+”、插入、填入、执行）为蓝色；永久删除和清空回收站保持原警示色 `#A23A31`。
- 选中态：浅蓝铺底 `#E6F4FF` 加蓝色文字，用于分类、视图切换、开关按钮、选中的素材卡片和片段、自绘菜单的选中项、筛选框中勾选的比例与标签。纯悬停仍用中性灰。
- 顶栏：五个页面统一为 `#0B6FCC → #0094FF` 的渐变（左侧 30% 保持 `#0B6FCC`，使标题上的白字不低于 4.5:1），白字，投影 `0 2px 8px rgb(0 0 0 / 12%)`，高 44 px。顶栏按钮白底蓝字，展开时为深蓝底白字；“本机”来源标记为深色半透明底白字，“局域网”为白底蓝字；焦点环为白色。这是全界面唯一的渐变。浏览器资源管理页由外框显示渐变顶栏，内嵌的素材与知识库页面顶栏改为白色面板，避免两道渐变。
- 层次：工作区 `#F7F7F7`，面板白色，分隔线 `#EBEEF5`。面板与弹窗圆角 8 px，控件 6 px，分类、来源、数量与检索框保持胶囊形。导入与占位框面板去掉描边，靠底色区分。
- 标题条：浅蓝 `#D0EBFF`、深色字、字重 600，用于排版工具各组标题、占位框面板标题与占位框列表标题、自检报告标题。
- 固定位置与弹窗：沿用现有结构，只统一间距；弹窗标题下加细分隔线，正文上方留 16 px。
- 节奏：尺寸按 4 px 取整（控件高 32、顶栏 44、弹窗操作按钮 36 等）。控件内 6 px 的上下内边距和 2 px 的细小间距保留，它们与 20 px 行高合成 4 px 倍数的总高。
- 焦点：白底、浅蓝底上为蓝色焦点环，顶栏上为白色；缩略图上的“+”和收藏按钮加白色内圈；文本框聚焦时改为蓝色描边。

**没有采用的规则：**

- 侧栏导航、页面标签栏、表格与分页：任务窗格宽约 320–560 px，素材以画廊而非表格呈现，这些结构会挤占素材区。
- 650 px 宽的弹窗：窗格放不下，弹窗保持 `min(440px, 100% - 24px)`。
- 60 px 顶栏：对窄窗格太高，取 44 px。
- 第三种操作色：只保留强调蓝和警示红两种操作色，避免选中态与操作色混淆。

## 验收方式
