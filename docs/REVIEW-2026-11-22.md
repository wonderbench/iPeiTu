# 代码审查（2026-11-22）

审查对象：`main` 的 `cdfb6d9`（PR #29 合并后），以及远端分支 `origin/Jzc` 的 `e9c1d1c`。

审查方式：逐个阅读 `main` 的服务端、WPS 桥接、排版工具、素材库窗格和安装脚本；阅读 `Jzc` 相对 `main` 的服务端、WPS 桥接、排版工具、安装脚本和文档差异。当前工作机没有 Node 和 WPS，本次没有构建，没有运行任何测试，也没有接触 WPS。下文都是读代码得出的结论。

## 结论

1. **`main` 已经不是项目的真实状态。** `Jzc` 从 `d594ad5` 分出，带有实机验证过的修复和大量新功能，但删除了全部测试和 CI。`main` 自 `d594ad5` 之后只合并了文档。
2. **`main` 上的占位框、填入和部分换图在真实 WPS 中会失败。** 原因是尺寸回读的容差过严，`Jzc` 已按实测修正，`main` 没有。
3. **`Jzc` 让局域网客户端可以永久删除整个图库。** 在改掉远程接口的放行方式之前，不应把 `Jzc` 用作局域网服务器。
4. **建议先把两条线合回一条，再继续新功能。**

## 发现

按影响从高到低排列。

### 高：`main` 的尺寸校验在真实 WPS 中失败

依据是 `Jzc` 的 `docs/WPS.md` 记录的实测（Windows WPS `12.1.0.29690`）：

- 占位框：设置 255.7 × 340.7 磅后回读为 255 × 340 磅，校验失败。
- 填入：12 × 9 厘米的框首次填图时，宽度由 340 磅变为约 339.6 磅，校验失败。
- 换图：横向 JPEG 换竖向 JPEG、JPEG 换透明 PNG 因高度回读偏差中止。

`main` 的对应位置仍是 0.1 磅容差：

- `public/wps-bridge.js` 第 456 行（占位框）
- `public/wps-bridge.js` 第 655 行（填入）
- `public/wps-bridge.js` 第 306—308 行（换图）

`Jzc` 另有以下修复，`main` 都没有：

| 位置 | `main` 的做法 | `Jzc` 的做法 |
| --- | --- | --- |
| `public/knowledge-bridge.js` 第 117 行 | 用内置样式编号设置标题，未经实测 | 用编号查到本地名称后按名称设置，回读样式名和大纲级别；标题 3、4、5 实测通过 |
| `public/layout-tools.js` 表格宽度 | 每行各自按比例缩放 | 整表用同一比例，避免含纵向合并单元格的表格错位 |
| `public/layout-tools.js` 删除空行 | 按选区内的段落序号判断两侧是否为表格 | 按文档位置判断，选区只含该空行时也能识别 |
| `server/fit.js` | 适配图不写分辨率标记 | JPEG 和 PNG 统一写入 120 dpi 标记 |
| `scripts/setup.ps1` | 换密钥时运行中的服务仍用旧密钥 | 生成新密钥前先停止服务 |
| `scripts/node-runtime.ps1` | 要求用户先装 Node.js 24 | 缺少时下载官方便携包并校验 SHA-256 |

### 高：`Jzc` 没有测试和 CI，带测试的版本不在远端

- `Jzc` 删除了 `test/` 下 13 个测试文件、`.github/workflows/ci.yml`、8 个浏览器验收脚本和 playwright 依赖。`package.json` 中也去掉了 `test` 和 `test:ui`。
- `Jzc` 的 `docs/PLAN.md` 写“204 项自动化测试通过”，`docs/ACCEPTANCE.md` 写命令“对应包含测试套件的开发版本”。远端只有 `main`、`Jzc` 和两个已合并的文档分支，那个开发版本只在某台电脑本地。
- 新增内容没有走 PR：浏览器资源管理页（步骤 15）、永久删除与清空回收站、编辑锁、实机自检入口、知识库粘贴带格式、界面重做、便携版 Node。这不符合 `AGENTS.md` 的三条约定：每步单独提交 PR；CI 全部通过后才能合并；路线文档没有列出的新需求先写入并经用户确认。
- `main` 上 11-10 的两份方案（`IMPROVEMENT-2026-11-10.md`、`DESIGN-2026-11-10.md`）写于不知道 `Jzc` 的情况下，其中实机自检页、界面重做、回收站清理与 `Jzc` 已做的内容重叠，需要对照后再决定采纳哪些。

### 高：`Jzc` 的局域网客户端可以永久删除图库

- 远程可用的接口按前缀判断：`server/lan-client.js` 第 19—22 行的 `isForwardedPath` 对所有以 `/api/assets/`、`/api/knowledge/` 开头的路径返回真，`server/http.js` 的 `remoteRoute` 据此放行。
- `Jzc` 新增了 `POST /api/assets/batch/trash`、`POST /api/assets/batch/purge`、`POST /api/knowledge/trash/purge`。它们因前缀匹配自动对远程开放。
- 清空回收站所需的 `revision` 可以从 `GET /api/library?view=trash` 读到。持有共享密钥的任何客户端都能先批量移入回收站，再永久删除。
- 密钥经明文 HTTP 传输，不分角色，也不能单独吊销某台客户端。`main` 上远程最多移入回收站，可以恢复；`Jzc` 上是不可恢复的删除。
- `AGENTS.md` 要求局域网接口“默认拒绝，只开放必要的路由”，并要求涉及局域网的改动合并前另行审查。前缀放行在 `main` 上就不符合前一条：以后任何新增的 `/api/assets/*` 接口都会自动对远程开放。
- 建议：改为“方法 + 路径”的显式白名单；永久删除只允许服务器本机操作。
- 次要：永久删除只清理 `images/`、`thumbnails/`、`insertion/`，不清理 `fitted/`、`insertion-quality/` 和客户端 `lan-cache/` 中的衍生图。

### 中：`main` 代码中的具体问题

这四项在 `Jzc` 上同样存在。

- **删除空行可能连带删除浮动对象。** `public/layout-tools.js` 第 125 行只按段落文字判断空行。锚定浮动图片或文本框的空段落，文字同样为空。按 Word 的行为，删除该段落会一并删除浮动对象；WPS 是否如此需实机确认。可在删除前检查 `ShapeRange.Count`。
- **插图和占位框的可用宽度不识别分栏和不确定宽度。** `public/wps-bridge.js` 第 61—72 行的 `availableWidth` 用整页版心宽度，两栏版面中图片会超出栏宽。合并单元格的 `Cell.Width` 返回 9999999 时，`Math.min` 取到版心宽度，不会报错。`public/layout-tools.js` 已用 `TextColumns.Count` 和 `UNDEFINED_WIDTH` 处理这两种情况，这里没有。
- **全文范围的排版没有确认。** `public/format.js` 第 54—58 行：未选中内容时，点一下“去除表格线”“删除空行”“一键去色”就作用于整篇文档，只有一次撤销兜底。
- **清除空格与路线文档的描述不一致。** `public/layout-tools.js` 第 68—84 行会删除中文与数字之间的半角空格，例如“张三 13800000000”会连在一起。`docs/V03-PLAN.md` 写的是“删除全角空格和单元格首尾空格”。需要用户确认规则。

### 中：图库变大后的性能

- **导入。** `server/library.js` 第 245 行每导入一张图都重写整个 `index.json`，批量导入的写入量随图库大小平方增长。第 515 行对重复图片每次都重写原图、缩略图和插入副本，且在判断重复之前已经完整解码并生成缩略图。
- **列表。** `GET /api/library` 一次返回全部素材；`public/app.js` 第 439 行的 `renderAssets` 每次检索都重建全部卡片，没有分页或虚拟滚动。
- **WPS 遍历。** 查找文字标记、删除空行、扫描占位框都按序号逐个访问段落或图片，每次访问是一次同步的宿主调用。每次填入成功后还会全文扫描一次占位框。长标书上的耗时需实机测量，实机待验清单第 5 项只覆盖了 `InlineShapes`。
- **知识库检索。** `server/knowledge.js` 第 162—165 行每次检索都对全部片段正文做 NFKC 规范化，片段多时会变慢。

### 低：其他

- `server/library.js` 第 169—173 行的 `replaceFile` 在重命名失败时不删除临时文件；`fit.js`、`placeholder.js`、`lan-client.js` 的同类写法都会清理。启动时也不清理遗留的 `.tmp`。
- `server/library.js` 第 493 行导入时使用 `failOn: 'warning'`，轻微损坏但能正常显示的照片会被拒绝。是否放宽为只在出错时拒绝，可按实际素材的失败情况决定。
- “原图”档插入时保留原文件的全部元数据（拍摄设备、位置等）。“清晰”“均衡”档会清除。暗标场景下可考虑提供插入前清除元数据的选项。

### 低：上次审查的遗留

`REVIEW-2026-11-09.md` 的建议中，README 的局域网安全前提已经写入（第 139、155、156 行）。以下几项在 `main` 上仍未处理：

- `fitted/`、`insertion-quality/`、`placeholders/`、`lan-cache/` 没有清理机制。
- 服务日志追加写入，没有轮转；认证失败每次写一行警告。
- `package.json` 的 `version` 仍为 `0.2.0`。
- `docs/PLAN.md` 标题和“服务只监听回环地址”等过期描述未改。
- `npm run check` 仍手工列出文件。

## 做得好的地方

- 本机请求同时校验回环地址、Host、Origin、`Sec-Fetch-Site` 和 Referer；静态文件解析真实路径后再确认位于 `public/` 内。
- 接口参数用白名单且不允许重复，JSON 字段必须完全匹配，请求体有大小上限。
- 索引、收藏、知识库和连接配置都先写临时文件再替换；文件损坏或版本不明时拒绝读取并保留原文件。
- WPS 写入前记录目标、写入时再次核对，写入后回读；失败信息区分“未写入”“已写入但未完成”“结果不确定”。
- 前端没有拼接用户数据的 `innerHTML`，只用于固定的图标。
- `Jzc` 的便携版 Node 下载固定版本并校验 SHA-256，永久删除用待清理记录保证重启后能继续，清空回收站要求确认时的版本一致。
