# 图片体积优化验收记录

## WPS 原图自然尺寸基线

2026-11-05，在 Windows WPS Office 12.1.0.29161 中使用步骤 5 代码和隔离图库，向 A3 横向测试文档插入五张自行生成的 600×400 图片。插件设置为自适应、最大高度不限制、原段落、不加图题。保存后解析 DOCX 的图片尺寸及内嵌文件 SHA-256，逐项匹配到测试源文件；这是真实 WPS 结果，不是模拟宿主结果。

| 输入 | 文档内宽 × 高（pt） |
| --- | --- |
| JPEG，移除 APP0 和 APP1 | 225 × 150 |
| PNG，移除 pHYs 和 eXIf | 450 × 300 |
| JPEG，300 dpi | 144 × 96 |
| PNG，300 dpi | 144 × 96 |
| Sharp 默认 PNG，pHYs 1000/m | 1047.15 × 698.1 |

最后一项已接近页面可用宽度 37 cm，受页面宽度限制，不能视为未限制的自然尺寸。无 DPI JPEG 与 PNG 结果不同，不能把读取库默认 DPI 值当成 WPS 的自然尺寸。测试文件仅保留在忽略的本地测试目录中。

## 质量档验收

Windows Edge 中运行 `npm run test:ui`，隔离临时图库通过。覆盖旧布局偏好兼容、质量偏好跨刷新、模拟 WPS 插入及替换请求传递均衡档，原图字节、清晰与均衡输出尺寸和体积、已知 DPI 逻辑尺寸、透明 PNG、旋转、小图不放大、无 DPI JPEG 标记与倍率、非法档位拒绝，以及原有 UI 回归。

压缩档的真实 WPS 插入与替换尚未验收；用户要求暂不操作 WPS，模拟宿主和以上原版基线均不能替代这项实机验收。

## 输出大小与无 DPI PNG 的直接 API 证据

使用独立临时图库和自行生成的 2600×1800、300 dpi 高细节 JPEG（固定伪随机像素、输入 JPEG 质量 95），从插入 API 读取各档实际文件并解码：

| 档位 | 像素宽 × 高 | 文件字节 |
| --- | --- | ---: |
| 原图 | 2600 × 1800 | 4,759,673 |
| 清晰 | 2400 × 1662 | 4,065,840 |
| 均衡 | 1600 × 1108 | 810,295 |

上述字节数仅对应这张生成样本，不代表所有图片的压缩比。另以去除 pHYs/eXIf 的 2200×1800 半透明 PNG 调用均衡档，实际输出为 1600×1309 PNG，保留透明通道；输出块仅含 IHDR、IDAT、IEND，没有 pHYs/eXIf，返回 `naturalWidthScale=1.375`，未返回 `logicalWidthPt`。这是隔离服务直接 API 与文件检查结果，尚未在真实 WPS 验证压缩档。临时图库已清理。
