# v0.2 与后续开发计划

用户于 2026-11-05 确认依次开发 1—3、4—7，并继续增加团队云图库与表格占位配图。每一步从最新 main 建立 codex/ 分支，提交单独 PR；主协调者结合交叉审查、检查结果与验收证据自动合并。

## 已确定的产品方向

- 产品：服务标书编制人员，在 WPS 文字内整理、查找并插入工程配图。
- 性格：沉稳、准确、直接；继续采用 unslop 的既有灰白、深青和 4px 间距规范。
- 主要内容：真实素材缩略图和预览；保持“搜索与筛选 → 图库 → 当前图片与插入操作”。
- 参数收纳：排版设置与素材整理放在可滚动对话框；320px 窄窗格仍保留清楚的插入入口。
- 识别细节：所选图片下方的图签展示规格与简短排版摘要，并给出插入目标（窄窗格在底部，宽窗口在右侧）；键盘操作不能意外写入文档。

## 云服务已确认的边界

- 暂无现成服务器：先交付可自行部署的软件、配置示例和运行说明，不宣称已对公网部署。
- 多账号共享团队图库，区分管理员和成员。第一版由管理员创建/管理成员并维护团队素材；成员可浏览、检索、上传、插入，收藏与最近使用按个人记录。
- 保留本机图库使用方式；云图库是新的可选来源。Windows WPS 插件仍通过本机组件处理下载缓存与嵌入图片。
- 服务地址、账号与密钥通过配置/登录提供，不提交真实凭据或用户素材。默认不开放公共注册。
- 先完成同一团队的共享使用及隔离验证；跨组织的运营、计费、公共素材市场不属于本轮。

## 验收与合并

- 每个 PR 写清触发场景、最终行为、运行过的检查与未覆盖范围；同账号审查用 COMMENT 记录，不能伪称独立账号 Approve。
- 代码、持久化与 WPS 操作契约运行必要回归；UI 修改在 320/420px 检查，重要流程纳入浏览器验收。
- 模拟 WPS 只证明调用契约，真实文字/图片/表格操作另记实机证据。用户正在编辑时不操作其现有标书，以独立测试文档验收。
- CI 失败、未解决的数据丢失/权限问题或主流程缺陷须先修复，再合并。
- 用户于步骤 6 要求继续开发、暂不操作 WPS。期间继续代码、浏览器及 API 验收与 PR 流程；受影响的 WPS 实机项保留待验，不以模拟测试替代。
- 每次合并后在本表更新可核对的 PR 链接；用户素材、缓存、账号数据和验收 DOCX 均保持 Git 忽略。
